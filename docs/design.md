# 设计决策

这份档案只回答一个问题：**为什么现在是这个样子**。每条都写成三段——**结论**是代码现在的样子，**为什么**是被哪个具体限制逼出来的，**代价**是因此放弃了什么。

要动手改代码，先读 [AGENTS.md](../AGENTS.md)：构建、测试、宿主契约边界、模块地图与坑位清单都在那里。这里只负责解释取舍；如果某条结论与代码不一致，以代码为准，并顺手把这里改对。

## 一、外壳、侧栏、标签、几何与配色

本部分覆盖应用外壳、图标栏与会话树、顶部标签、圆角标尺与配色。每条都按「当时的结论 → 为什么 → 代价」记录，覆盖 README「## 外观」第 7–29 行。

### 布局与滚动

**外层固定在视口内，各区域自己滚动。** 应用外层固定在窗口视口内，侧栏、对话和问答内容分别内部滚动。聚焦输入框或把某个区域滚到边缘时，不带动整个页面下移。代价是每个区域都要单独维护滚动位置和观察器，测量顶部标签栏、标题行时也只能以容器内部坐标为基准，不能指望「整页滚动」帮忙。

**窗口按钮不再铺自己的底色。** 桌面窗口右上角的最小化 / 最大化 / 关闭按钮，preload 测量 probe 的填充改为 `rgba(0,0,0,0)`，原生 Window Controls Overlay 以 0% 透明合成。按钮字形仍取 `label-primary`，页面表面直接透出。代价是这条路径依赖 preload 与 WCO 的合成链，probe 的透明值一改，按钮底色就会重新显形。

### 字体与文字层级

**深色模式正文分三档，按亮度同比提亮。** 正文 `#f1f2f4`，次要文字 `#c3c5ca`，辅助文字 `#b4b7bf`。三档按 OKLCh 亮度同比提亮，层级之间的间距保持不变。代价是三档要整体同调移动，单独改一档就会破坏层级间距，新增文字色也得先落进这三档。

**字体跟随宿主，皮肤不覆盖。** body 继承宿主的 `--dsw-font-family`（DSH 0.2.1 的文字字体选择）；旧版没有该用户变量时回退到原来的 Segoe UI / 微软雅黑 / PingFang 栈。代码与终端的字号由宿主自己的 `--dsh-code-font-size` / `--dsh-terminal-font-size` 控制，皮肤不覆盖。代价是皮肤对字号没有话语权，宿主改字体或字号时只能跟随，回退栈也只为旧版存在。

### 配色与表面

**五层表面靠底色分层次。** 图标栏 `#191b1d`、侧栏 `#202123`、主工作区 `#292c2e`、顶部标签栏与表单 `#303335`、输入卡片 `#323537`。图标栏通过背景色区分层次；主面板向会话列表投射两层外阴影，沿圆角轮廓形成抬高的层次；输入卡片的信息栏略亮于编辑区。代价是层次全靠明度差维持，没有边框托底，任何一档取值偏移都会让相邻两层糊在一起。

**浅色选中胶囊按标签栏自己的底色配平。** 同一个 `--smooth-selected` 令牌，落在近白的标题栏上是 **1.31:1** 的一块深色，落在侧栏的灰底上却只有 **1.12:1**。浅色主题因此把它按 **46%** 混回标题栏表面，三种浅色预设都落到 **1.13:1**，和侧栏选中行同重。

**悬停两态按同一口径重配，深色主题不动。** 选中态悬停再加深一档到 **1.19:1**；未选中标签的悬停改成一抹 **4%** 文字墨（**1.07:1**），而不是原来的灰色层——否则悬停比选中胶囊还靠近底色。深色主题仍用原令牌，那里的标题栏底色本来就与它同调。代价是浅色下多出一条按主题分支的混色规则，新增预设时要重新核对这三个对比度。

### 圆角与几何标尺

**顶部标签栏是固定尺寸的 chrome。** 标题栏高度钉在 **48px**、标签条左上的圆角钉在 **18px**、左右内边距钉在 `35px / 5px`。左侧栏与工作区之间的分界渐变直接落在侧栏右边缘，不再往工作区里多留 18px：标签条底板从那一点起就是同一种 surface，否则标签条左侧会露出一条侧栏色的窄带。左上角的 18px 圆角由标签条自己的一枚 18×18 角块补出——只画半径外的楔形（侧栏玻璃色），所以圆角看得见，又不带回整条侧栏色带。原来是 `clamp(48px, 65 * 100vw/1950, 64px)` 加 `35 * var(--smooth-u)`，窗口一宽这排背景就跟着长高、变圆；标签本身早就用固定单位（`--smooth-tab-u: .65px`），现在整条标签栏都是定值。代价是宽窗口下这排 chrome 不再随视口联动，也不再随窗口放大。

**几何按 1950px 画布定，但不再随窗口放大。** 主面板、原生图标底板和输入框圆角按样例比例缩放，形状按 `--smooth-u: min(1px, 100vw/1950)` 计算；左栏 chrome 直接钉死（`--smooth-l: .91px`，参考文件对侧栏栏位用的就是这个值），标题栏高度停在 64px。代价是缩放只在小视口生效，大屏上取的是画布比例的上限值，观感不再随窗口继续变大。

**圆角统一到五档标尺。** 皮肤自绘的矩形一律取 `--smooth-radius-xl/lg/md/sm/xs` = **26 / 16 / 11 / 8 / 4px**；宿主侧 `--dsw-radius-panel/xl/lg/md` 同步为 26/26/16/11，`sm/xs` 沿用宿主默认 8/4。分配是：外壳左下角与大面积面板 26，菜单 / 弹层 / 卡片 / 输入井 16，输入框 / 选项卡 / 图标栏按钮 11，列表行与小按钮 8，16px 图标按钮 4；胶囊与圆形仍用 999px / 50%。

**例外也写进规则里，不再散落。** 只有标题栏左上角 18px（窗口 chrome）、嵌套内圆（外圆减内衬，如筛选内选项 `8−2=6`、模型媒体图 `16−1=15`）和数据小色块（热力格 3px、色块 2px）保留字面值。原先 14/15/19.5/10.92/9.1 等散落取值、视口相关的 `calc(35 * --smooth-u)`，以及被覆盖的旧设置弹窗 / 导航 / 新会话圆角都已收口。代价是新增组件必须先从五档里挑，嵌套圆要手算，例外清单也会持续累积。

### 侧栏与会话树

**图标栏是固定尺寸的紧凑竖条。** 原生导航按钮与头像组成左侧图标栏：栏宽约 38px、按钮 35px、图标 22px，不随窗口变化，按钮沿栏中线对齐；项目树、新会话和品牌显示在右侧。按钮与图标保持原尺寸，只把图标栏底色收窄到贴着按钮。代价是栏宽被钉死，宿主改按钮尺寸时这里不会自动跟随，只能再手调这几个值。

**「新版本」更新 pill 收成方形按钮，浮在 footer 上方。** 桌面更新 pill 在栏内收成与其余按钮同尺寸的方形按钮，并浮在 footer 上方、独占一行：`position:absolute` + `bottom:calc(100% + 8px)` + `translateX(-50%)`，footer 是包含块；文字按设置按钮的方式只做视觉隐藏（`aria-label` 与 tooltip 仍带版本信息）。

**不能留在那一行，是因为 footer 本身是两行横排的。** 宿主把 footer 排成两行（账号行 + 设置行），而设置行本身是横向 flex，单列栏放不下就会横向溢出、落到头像背后；`order` / `display:contents` 这类换序手段又受宿主的嵌套层级影响，所以直接把它抬出那一行，位置不再依赖内部结构。代价是定位依赖 footer 这条包含块链，宿主重排 footer 就要重新核对。

**pill 外观改回栏内按钮，只保留品牌蓝图标。** 去掉宿主给的品牌蓝描边与 8% 蓝底，换成透明的底与 `--smooth-surface-3` 的悬停填充；图标保留宿主那支新版本蓝 `--dsw-alias-brand-primary-new-colorprimary-new-color`（悬停也不变色；忙碌中的 `aria-disabled="true"` 不显示悬停，错误点仍是红色）。旁边的连接指示灯带 `data-phase`、不带 `aria-disabled`，因此不会被这条规则命中。代价是选择器贴在这两个属性上写，宿主一改属性名就会漏掉。

**面板列表的「更多」用 `order:1` 固定在图标列最末。** 第三方面板行（如记忆库）会把自己追加到宿主 `panelList` 的末尾，只靠 DOM 顺序它会跑到「更多」上面；用 `order` 才能无论后来插入什么都保持在最底部。代价是多一个排序约定，与新面板插入逻辑耦合。

**会话树按参考列表收紧，行高与字级一起收。** 会话行 **28px**、工作区行 **29px**（原生 32 / 34）；会话名 `12.5px/18px` 用次要文字色；工作区名 `13.5px/19px` 统一用宿主 `--dsw-alias-label-primary`、字重 400；时间是 `11px/16px` 且与会话名同色（原生 10px、比标题暗一整档）；顶部「工作区」标签 12px。

**字重取 400，是因为中文回退字体没有 500 档。** 原先 500 只在拉丁文字上落到 Segoe UI Medium，中文回退字体没有 500 档，导致「默认工作区 / 未分组」看起来比 free 等标题更浅。代价是这组数值都是替宿主写死的覆盖，宿主换字号时要重对一遍。

**工作区行不画文件夹图标。** 标签直接落在列表自身的左边距上。代价是行首少一个形状提示，也不再有点击文件夹图标的入口。

**行首空心点与宿主 spinner 共用同一份几何。** 行首那个 16px 前导格里画一个空心点：`r=9.5`、`stroke-width=2.71`、24 单位 viewBox、按 8.84px 显示，也就是外径 **8px**、线宽 **1px**。

**两种状态由同一条矢量路径绘制。** 空闲时这个圆是 `::before` 上用同一支 SVG 做的遮罩（`mask` + `background: color-mix(次要文字色 72%)`）；进行中由宿主自己的 spinner 顶上来（圆点 `opacity:0`，轨道压到 40%，圆环轮廓还在、转动的亮弧更显眼）。所以两种状态圆角完全一致——先前用 CSS `border` 画的圆环和 spinner 的矢量描边圆角对不上，一大一小两个圆。

**直径取 8px，而不是参考图的 6px。** 参考图是 6px，但 150% 缩放下只有 9 个物理像素，边缘会被读成圆角方块，所以取 8px（12 个物理像素）。行首永远是同一个大小、同一个位置的圈，进行中只是转起来。

**文件夹与悬停时才出现的三角都不画。** 它们和状态圈共用同一个 16px 格子，两者一律不画——只藏其中一个的话，指针进入行时标签会横移一格。代价是丢掉「这是个文件夹」和「这里有操作」的形状提示，改由行内文字与整行悬停态承担。

**归档行末尾多一个删除按钮。** 只有归档行才渲染，注册在宿主的行操作槽 `sidebar.workspaces.session.row.action`，`order: 300`，排在归档 / 置顶之后；按钮是宿主的紧凑图标规格（14px 图标 / 20px 命中区），悬停才转成错误色。代价是它绑在宿主的行操作槽与 `order` 排序上，槽位或序号变化就要跟着调。

**删除走两次确认，再由 Host 半动手。** 点击先弹原生 `Modal` 确认（「将永久删除『标题』的本地会话记录，无法恢复」），确认后由 Host 半的私有桥接删除该会话的持久化日志目录与其投影缓存，再重拉会话列表，归档行即时消失。

**只删「已归档且没有仍在运行的活动」的会话。** 宿主的归档只会停掉工作、不会把 Agent 从内存 store 里清掉，所以内存里仍有这个会话也可以删。

**删除前先过归档准入，再做收尾。** Host 半先询问归档准入所问的 `workspace/session-activity` 提供方，仍有运行的轮次 / 任务 / 子代理 / 计划任务会拒绝删除；空闲时再通过 `workspace/session-stop` 收尾，并顺带清掉工作区记账与投影缓存。如果该会话仍留在宿主的内存 store 里，删除后会把对应的 store 条目摘掉（控制器把随后的 `session/disposed` 转成 `api-session/removed`，客户端刷新后不会把归档行加回来）。

**Host 半不可用时会报错，改过 Host 半要完全重启。** Host 半不可用时对话框会显示错误；修改过 Host 半（`lib/index.js`）后需要完全退出 DSH 再打开才生效。代价是删除链路横跨客户端与 Host 半，出问题要两边一起看。

**新会话按钮收成 30 单位高。** 原来是 46，上下各留 2 / 3 单位边距。侧栏列表顶部分隔线与右侧会话头部底边因此落在同一水平线（实测 162 / 161px），不再一高一低。代价是按钮比原生矮一截，命中区也随之缩小。

**悬停左侧区域时浮出「进行中 / 已归档」分段按钮。** 它出现在「工作区」标题那一行，选中项高亮，`24px` 高、圆角 `8px`、字号 `12px`；点一下就在运行中的会话与归档之间切换。它直接读写宿主工作区浏览器自己的视图状态（`archivedFilter`），所以和「...」菜单里的归档筛选是同一份，不另存拷贝。

**控制条跟着标题行一起量。** 控制条固定在量出的标题行上（窗口缩放或侧栏展开时跟标题栏一起重新量），侧栏收起或搜索展开时让位，键盘焦点进入时也会显示，减少动态效果时不淡入。按钮使用 `aria-pressed`，因此读屏和自动化都能读到当前的选中侧。代价是多一条要跟着宿主标题行重测的定位。

**收起再展开时左侧宽度保持不变。** 宿主折叠侧栏后会用自己默认的 280px 重新打开，皮肤记住收起前的宽度（默认 352px，或用户拖出来的宽度），只在这个 0 → 280 的切换里把宽度写回，并把 `--smooth-left-width` 同步成同一数值。如果用户本来就手动拖到 280px，则不会被误改成 352px。代价是这条规则只在那个特定切换区间生效，其他宽度变化仍交给宿主。

**对话列宽度会被记住。** 宿主把拖动结果写进 `localStorage`（`dsh.conversation.contentWidth`），插件在启用时把这个宽度同时存成插件默认（`dsh.smooth.conversationWidth`）、写回宿主并同步页面上的 `--dsh-chat-user-width`，重载或宿主偏好被清掉后仍按这个宽度打开。

**没有拖动记录时按当前正文宽度兜底。** 没有拖动记录时，直接把当前显示的正文宽度（宿主发布的 `--dsh-chat-user-width` 或计算出的 `--dsh-chat-content-width`）记为默认。代价是同一件事存了两份，宿主偏好与插件默认之间需要靠写入时同步来保证一致。

### 顶部标签与 Home

**侧栏默认宽 352px，并给标签条让出位置。** 宽度保存自当前布局，不再按窗口宽度的 28.5% 重算；仍可手动拖动，关闭皮肤时保留手动宽度。顶部标签条的高度直接取宿主的标题栏高度（桌面端 40px），标签本身尺寸不变，只收掉上下多出来的留白。

**标签先占预览位，发出第一条消息才固定。** 新建的会话先占一个可替换的临时预览标签，只有真正发出第一条消息时才固定成标签（打开、点按钮、打字都不算）；从会话树里点开的会话同样先占预览位，在正文里操作后固定。新标签排在最前面：预览标签占最左位，固定后仍留在原位，更早的标签依次往右，溢出时才出现滚动箭头。代价是标签位置与「是否发过消息」耦合，判定条件改一次就要重验一遍。

**收起侧栏时，标签条左边界按量出来的原生控件定位。** 皮肤量出原生「应用 / 编辑」菜单的右边缘再留 8px，左侧依次是 12px 的展开箭头、48px 的新会话按钮和菜单本身；箭头与新会话按钮都由宿主固定在标题栏同一水平线、同为 28px（面板按钮量不到时回退 100px）。这样标签不会再压住或挤歪它们。代价是边界不写死，窗口缩放或面板开关时都要重测。

**归档会话的标签随之下线。** 标签账本订阅宿主工作区快照里的 `archivedSessionIds`，归档发生时把对应的预览 / 固定标签一并移除。如果归档的是当前会话，宿主本就会清空主视图，标签条不会留下一个打不开的入口，也不再有标签处于选中态。已归档的会话不会被重新加回（在仍打开的归档对话里点按、发送都不会复活标签）。代价是取消归档也不会自动恢复标签，需要重新从会话树打开。

**Home 用线条房子图标，按有没有会话标签分两种行为。** **有会话标签时**只关掉压在它上面的设置或面板，回到那个会话（标签和对话都原样留着，已经在主页面时再点不动）。

**没有会话标签时，Home 直接回欢迎页。** 只剩设置 / 插件标签、或标签已经全关掉时，宿主会把最后那段对话继续留在主视图里，此时只关设置和面板会露出一个标签条已经不代表的页面；所以点 Home 会把主视图一并清空（`clearMain()`），标签条上也不再有任何一页是「当前」（`clearActive()`），主视图因此是宿主首页，`data-smooth-home` 一挂上就是带用量面板、不带输入卡片的欢迎页。新建仍使用「新会话」按钮。

**设置标签会回到离开时所在的分区。** 点回「设置」标签会回到离开时所在的分区，而不是宿主的「通用设置」落地页——宿主关闭设置时会清空自己的 `activeId`，皮肤从设置存储的快照里记住最后显示的分区（第一次打开仍是通用设置）。代价是这份状态存在皮肤侧，快照丢了就退回通用设置。

**会话头部按参考排版重排。** 标题占第一行（左），「智能体团队 / 创造模式」等挂在 header actions 槽位里的标签落到标题下方第二行，**对话 / 轨迹** 两个胶囊居中压在标题那一行上。

**把宿主那一整行抬到标题行顶部并居中。** 宿主原本把这两个标签和「更多会话视图」（`…`）按钮一起放在头部网格的第二个整行里（标题行下面靠左），皮肤把整行绝对定位到标题行顶部并居中——`…` 按钮紧贴在胶囊右侧，两者同排显示。

**左侧占位与两行 grid 一起把胶囊钉在中线上。** 左侧用一个只在按钮存在时出现的等宽占位，让胶囊本身仍然落在头部中线上；再把标题簇从一行 flex 拆成两行 grid（面包屑一行、actions 一行），标题行右侧的 utilities / corner 仍靠右，并与标题那一行对齐。

**头部整体收紧。** 内边距 4 / 18 / 6 / 14px、`min-height:0`、标题簇行距 1px，标题与元信息两行的间距因此比原生矮一截。代价是这套数值绑在宿主的头部网格上，宿主改网格就要重调。

**对话 / 轨迹换成滑块式切换。** 一条胶囊轨道里一块 50% 宽的滑块，选中项靠 `:has(>[role="tab"]:nth-child(2)[aria-selected="true"])` 把它 `translateX(100%)` 推过去，`.26s cubic-bezier(.22,1,.36,1)` 平滑过渡。

**这一行默认隐藏，用到才淡入。** 默认 `opacity:0`，鼠标进入会话列（或键盘焦点落到控件里、或「更多」菜单展开）才 `.18s` 淡入，离开淡出——「更多」按钮与胶囊共用同一个显隐条件，一起出现、一起隐藏。

**命中区只留给胶囊和「更多」。** 抬起后的整行仍然铺满头部宽度，但行本身 `pointer-events:none`，只给胶囊和「更多」重新打开命中区，否则这层透明整行会盖住标题行右侧的 header actions（智能体团队、打开方式分体按钮）与 utilities / corner，按钮看得见却点不到。只有底色还是皮肤自己的。

**顶部标签可直接拖动重排。** 指针移动超过 4px 才进入拖动，普通点击切换 / 关闭不受影响；拖动中在目标插入间隙显示 2px 的 `|`（不贴标签边框），松手只改顺序、不激活标签。预览标签被拖动后会固定并落在被拖到的位置，没有拖动的预览始终占最左位（往它左边拖的固定标签会落在它右边）。代价是预览标签一旦被拖动就变成固定标签，预览位随之让出。

**滚动箭头浮在标签条上，不占布局。** 左右箭头是浮在标签条上的绝对定位按钮，不作为 flex 项占 22px + gap；出现或消失不会改变标签条宽度，因此不会压缩标签，也不会让 overflow 观察器来回切换而卡顿。标签条右侧留出箭头自己的槽位（`padding-right: 30px + 10u`），标签内容在箭头前一个缝隙处就被裁掉，所以「点箭头」不会点到压在同一点上的标签关闭按钮。

**箭头只在该方向真的还有内容时才出现。** 滚到最右端，右侧箭头跟着收起，而槽位留在标题栏自己的内边距里，所以标签不会因为按钮消失而移动。代价是那段槽位始终占着，即使两侧都已到尽头。

**鼠标在标签栏上滚动时映射成横向滚动。** 上滚向左、下滚向右，以平滑缓动累积连续滚轮位移；保留触控板横向滚动，支持对话页与设置页，减少动态效果模式下直接滚动。

## 二、主题、设置、欢迎页、账号菜单、内容区与启动动画

覆盖主题预设与标记色、背景透明度、整页设置的尺度与分组、欢迎页与用量面板、账号菜单、会话内容区的几处收敛、滚动条，以及桌面窗口尺寸为何只能走 `resizeTo`。每条按「结论 → 为什么 → 代价」记：结论是代码现在的样子，为什么是被哪个具体限制逼出来的，代价是因此放弃了什么。

### 主题预设与标记色

- **六套预设替掉日夜两档。** `设置 → Smooth → 主题` 可选「跟随主题 / 初雪白 / 玄铁黑 / 苔痕绿 / 落日橙 / 深海蓝」，默认「跟随主题」：跟随主题时浅色实际用初雪白、深色用玄铁黑，由宿主明暗切换驱动。每套预设都带完整调色板（背景、导轨、面板、文字、边框、品牌色、滑杆与状态色），切换时通过宿主的 `overrideTokens` 同时写 light / dark 两档；固定预设两档取同一套颜色，所以宿主明暗怎么变都是该预设。代价是每套预设要维护两档的全部变量，新增一档就得把两档都填满。
- **预设接管明暗之后，宿主里不再有第二个开关。** 选固定预设会把宿主明暗临时切到该预设的色调，退回「跟随主题」或关闭皮肤时再还原，因此宿主「通用设置」里不再出现第二份日夜模式控件，只保留顶部「通用设置」标题。代价是主题色调的所有权在皮肤与宿主之间来回交接，还原时机必须两处都覆盖，漏一个用户就会卡在预设色调里。
- **旧状态自动迁移。** 旧版本存下的 `light` / `dark` 会自动迁移成「初雪白」/「玄铁黑」，升级后不用重选，也不会因为字段名变了而退回默认主题。
- **标记颜色只写宿主的一个变量。** 「标记颜色」提供蓝 / 青 / 紫 / 绿 / 橙 / 玫红（默认蓝），这一个选择写入宿主的链接色 `--dsw-alias-link`，改变对话里的引用文件与重点提示（链接色文字与行内代码）；切换立即生效并写入 localStorage，随「恢复默认设置」回到蓝色。代价是标记色没有独立作用域，凡是宿主用链接色的地方都会跟着变。
- **工作区标题不染色。** 左侧会话树里的工作区分组名称曾短暂用 `--smooth-mark` 染蓝，已移除，标题只保留字号 / 字重的调整，会话标题保持原来的层级。理由是会话树是导航结构，颜色一进来就会和「选中 / 未选中」的状态色抢同一块面积，而标题本身只需要压过会话标题。代价是标记色在侧栏没有落点，只能靠内容区体现。

### 背景透明度

- **整页只有一层透出。** 通透度是 body 上的一个内联变量 `--smooth-glass`（表面色的权重百分比）：页面底色、侧栏、导轨与顶部窗体条各自用 `color-mix()` 从调色板色和这个权重派生半透明色，底纹画在 body 的负 z 层，所以整页只透出一层。默认 5%，0% 时所有表面回到实心，与旧版一致；设置行是 0–100 的滑杆，随皮肤关闭一起撤销。
- **为什么要自己画底纹。** 没打下面的窗口补丁时，桌面窗口本身不透明（Windows 上没有 vibrancy），页面的「通透」没有桌面可以透，只能透出皮肤自己的东西；底纹因此是三层随主题走的径向渐变（品牌色 + 暖色叠在页面底色上），六套预设各带自己的色。代价是这份渐变是皮肤凭空加的，关掉皮肤后页面里没有对应物。
- **真正的桌面透明靠安装包补丁，不在插件里。** 渲染进程没有任何 API 能改操作系统窗口，亚克力必须由 Electron 主进程在创建窗口时给出：`tools/patch-window-glass.mjs` 直接改已安装的 `resources/app.asar` 里的 `lib/main.js`——主窗口 win32 分支加 `backgroundColor: "#00000000"` 与 `backgroundMaterial: "acrylic"`，并在窗口的 `did-finish-load` 上给页面 `<body>` 打 `data-smooth-window-glass`。补丁靠裁剪同一文件里的注释文字把修改压成**等长原地写**：asar 头、偏移和其它文件都不动，所以补丁可以在 DSH 运行时打，下一次启动才生效，也不存在「新 preload 配旧主进程」的错配；皮肤看到属性才把底色交出去（`html` / `body` 透明、去掉内嵌底纹）。选亚克力而不是 `transparent: true`，是因为系统磨砂能保留窗口阴影、圆角与缩放行为。代价：这是对**已安装应用**的修改而不是仓库产物，DSH 每次更新都会覆盖、需要重跑补丁；补丁只在 Windows 11 上有效（macOS 本来就有 vibrancy）；`main.js` 里会少掉一小段注释（为了等长），锚点对不上时脚本拒绝修改；一旦窗口透明，页面里任何没被皮肤接管的像素都会直接露出桌面，所以 `html` / `body` / frame / 中栏 / 侧栏必须全部由皮肤负责。
- **页面填充只留在中栏。** 每个表面各自透出会叠层：两层 70% 表面叠在一起只剩 9% 透出，30% 的通透度会被乘成 9%。所以中栏是唯一画 `--smooth-app-glass` 的地方，侧栏画 `--smooth-sidebar-glass`，中栏内部的标题行、会话滚动画布与插件页一律 `background:transparent`，不重复叠半透明。frame 背景因此不再铺整块的侧栏色；中栏左下圆角切出的 26px 缺口改用一枚 `radial-gradient` 图块按 `--smooth-left-width` 定位补回侧栏玻璃色，所以 0% 时缝隙与旧版一致，通透时缝隙跟着一起淡出。代价是这枚图块的位置钉在中栏圆角上，宿主改圆角尺寸或换成四角圆角时要同步改。
- **通透只给大块底板，组件只轻微跟随。** 跟着滑杆走的是页面底色、侧栏、左侧图标栏、标签条与输入区底板这些「区域底板」；按钮、列表行、标签芯片、卡片、输入框等组件用一层很轻的权重（每 3 点通透度降 1 点不透明度：30% 时约 90% 不透明，100% 时 67%），拖滑杆时组件会轻微变化，但看起来仍是实心的，不会发虚，也不会丢掉选中/悬停的层次。图标栏坐在侧栏玻璃上，若用页面权重会叠成只剩 9% 透出的实心带，所以它改用更陡的权重（页面权重的四次方，30% 时约 24%），0% 仍是 100% 的旧底板。标签条不再叠在窗体条的 surface 上：窗体条只铺侧栏那半（`0..--smooth-left-width`），标签条自己从侧栏边缘铺 surface 到右边缘——单层、和对话区同一权重；左上角 18px 角块的侧栏色因此只叠在桌面/亚克力上，和侧栏完全同色，不会在 50% 时发灰。工作区列表底部 24px 的虚化由宿主 `dsh-client-ui-workspace` 的 `.GAkraW_fade` 用 `--dsw-specific-sidebar-fill` 画，皮肤在 `#root` 里把该令牌改成 `--smooth-sidebar-glass`，虚化才和侧栏一样透；虚化元素本身再单独用更陡的 `--smooth-sidebar-fade`（页面权重的四次方：30% 时约 24%、50% 时约 6%、100% 时 0），所以它比页面更快消失，拉满时完全透明。浮层菜单（账户、模型、Git、右键菜单）与整页设置只透一层很淡的底板：客户端给它们单独一个权重，每 8 点通透度才降 1 点不透明度，最低 85% 不透明，所以下面的正文不会透上来；里面的菜单项、表单行、按钮和输入框保持实心。代价是浮层与页面的通透度不同步，滑块拉到最大时它们仍接近实心。代价是「区域」与「组件」的界线要靠人判断——新增一块区域面板时要用 `*-glass` 令牌（`--smooth-app-glass` / `--smooth-sidebar-glass` / `--smooth-rail-glass` / `--smooth-surface-glass`），新增控件时用 `--smooth-surface*-mild` 令牌；`#root` 内的宿主控件由 `--dsw-alias-bg-layer-*` / `--dsw-specific-input-major` / `--dsw-specific-bubble` 的 mild 改写覆盖。

### 整页设置

- **尺度改回宿主自己的那一套。** 插件页保留原生布局、图标、列表和开关，但整页设置不再沿用样例图的大画布比例，改用 Harness 自身的界面尺度：表单 52px 行高、14px 标题、13px 说明、30px 选择器、36 × 20 开关。样例图是按整屏海报画的，套进应用会得到一行只放两三个控件、必须滚动才看得完的设置页；换成宿主尺度后，设置页和它旁边的原生页看起来才是同一个应用。代价是整页的视觉张力下降，第一眼不再像一张产品图。
- **主题预设收成一行六格。** 每格是色板点 + 名称的小卡片，不再有日夜模式的三列开关卡片——日夜已经在预设里表达过了，再摆一列开关等于让用户对同一件事选两次。
- **切预设用一次从左上角展开的圆形揭示。** 切换前先快照旧页面，新调色板的快照被裁进一个从视口左上角向外扩大的圆里（`.52s` 缓出），圆内已是新主题、圆外保持旧主题，两张快照不做交叉淡入；快照期间宿主色调与 `--smooth-*` 令牌已同步写完，并等一帧让设置页的选中药丸也画好，再取「新」快照。只有真正改变当前色调下配色的切换才播（`auto` 与它当前解析到的预设互点不播动画），减少动态效果、平台没有 `startViewTransition` 或界面不可见时直接切换。连续点预设时旧快照被新一次替换，不会把过时主题写回去，快照期间改的其它设置也不会被主题写入回滚。代价是主题切换多了一帧快照等待，还要自己处理并发切换的竞态，这两件事都比直接改 CSS 变量重。
- **左侧导航按参考截图取尺度。** 面板标题 20px/700，导航项 15px/22px、34px 行高、18px 图标、图标与文字间距 13px，选中项是 8px 圆角的浅色填充。左侧因此是「一块文字」而不是一列小字，文字在栏宽里的占比明显提高。代价是导航项更占高度，一屏能列出的条目变少。
- **导航分成三组，但分组是位置锚定的。** 「账户 / 应用 / 扩展」里，应用组收拢通用设置、模型、内置插件与 Agent 预设，扩展组收拢提示词优化、插件市场、Smooth 皮肤与侧边卡片（原先的「外观」标题并入扩展，市场 / 皮肤 / 卡片都是插件提供的条目）。代价是宿主把 `settings.section` 渲染成一个扁平列表，导航项身上没有 id 或分组属性，分组标题只能按位置锚定，增删设置项会连带移动分组边界。
- **分组标题坐在 34px 的空隙里。** 分组标题与条目同号（15px/500，灰色），占住组内第一个条目上方的 34px：4px 留给上一组、20px 是标题自己的行盒、10px 留给本组第一项，所以分开三组的是标题本身而不是空行；`navList` 的 `padding-top` 也留到 34px，否则第一个分组标题会被滚动容器裁掉。代价是这套几何写死在数值里，宿主改行高或字号就得同步改这几处。
- **设置打开时放行宿主点击。** 整页设置占住工作区右侧后，宿主的模态浮层和透明遮罩改为 `pointer-events:none`、只让面板自己接收点击，所以设置打开时左侧栏图标、顶部标签条与 Home 都能点；点侧栏里的面板会先关闭设置再打开对应页面。账户菜单的浮层（1100）仍盖在设置（1000）之上。代价是「哪一层收点击」从此由皮肤判定，宿主新增遮挡层时要再补一条。
- **皮肤页按「外观 / 启动」分组，所有改动即时保存。** 标题旁有一枚实时状态徽标（已启用 / 已关闭）；窗口尺寸行在说明下显示当前窗口的外框尺寸，并提供行内「恢复 1440 × 900」——只重置宽高这一对数字，不碰开关、不碰窗口；底部「恢复默认设置」旁注明「更改会自动保存」。所有改动即时写入 localStorage，没有单独的保存按钮，代价是没有「撤销本次编辑」的余地。
- **开关尺寸只对宿主通用设置行重申。** 皮肤不再全局改写 `[role="switch"]` 的尺寸与配色，只对宿主「通用设置」行里的原生开关重申 36 × 20 的默认几何，插件页的开关 / 按钮保持各自样式。旧规则会把插件自带的开关重绘成白底、大号深色圆钮并顶出容器，技能中心等插件页因此显示异常；代价是宿主若在别处改了开关默认几何，皮肤只跟上这一行。
- **那枚 ✕ 是真的被删掉了。** 顶部标签条就是离开设置的通道（点标签、点「主页面」、按 Esc 都行），所以原生关闭 ✕ 被去掉：它紧贴在页面自己的动作按钮（例如「通用设置」右上角的「打开配置文件」）右边，看起来像同一颗按钮上粘了个叉，而参考图里那个位置本来也没有 ✕。除此之外皮肤不隐藏任何宿主内容：`display:none` 只出现在参考图里同样不可见的装饰性预览徽标、插件自己可折起的余额面板，以及这枚关闭按钮上。

### 欢迎页与用量面板

- **欢迎页交回宿主的堆叠与占比。** 标题（含原生「预览版」徽标）、工作区胶囊、输入卡片依次排列，卡片宽度由宿主 `--dsh-composer-card-max-width` 决定（与对话中同一个上限）。早期版本把标题、工作区行和卡片各自绝对定位（`40.65%` 系列偏移、卡片钉在下半屏并压到 150px 高、`max-width:none`），这些位置规则已删除，改为在 `[data-conversation-scroll]` 与 `[data-composer-seat]` 上显式 `justify-content:center`，所以整块在窗口里居中且占比与参考图一致。代价是皮肤不再能把卡片按画布像素摆到任意位置，窗口尺寸一变只能跟着宿主的堆叠走。
- **皮肤自己的文案只留标题里的产品名前缀。** 那一行工作区（皮肤的「工作区」标签 + 原生工作区选择器 + 它带的分支）连下面那行「在这里开始新的对话。」都不画，因为卡片自己的信息栏已经写了工作区与分支，那一行只是重复一遍。隐藏写在 `heroWorkspaceRow` 上（`display:none`，其 `::after` 随之消失），而「工作区」标签与那句话的规则仍留在源码里，改一行就能把整行放回来。代价是这条规则在样式表里留了一份暂时用不到的代码。
- **卡片按「主视图是什么」出现，而不是按标签数量。** 宿主停在首页时（应用刚启动、标签全被关掉，或点了 Home 把对话清掉而标签还在）只有标题，输入卡片不画；一旦有会话 / 面板 / 设置显示，卡片以 `.26s` 淡入（减少动态效果时不播）。开关由浏览器半按宿主当前视图发布在 `body[data-smooth-home]`（`src/layout.js`），样式在 `src/skin.js` 读它，关掉皮肤时随皮肤一并撤掉；它不看标签数量，因为 Home 会清掉对话却把标签留在标签条上，那一刻显示的仍然是欢迎页。输入卡片按它自己的 `data-composer-card` 属性选中，不依赖它在宿主里的层级——宿主把 composer 挂在自己的 slot 包装层里，子代选择器会漏掉它。
- **工作区切换菜单是皮肤自己画的那一枚。** 注册在宿主的 `conversation.hero.workspace` 槽上，用 `decorate` 以 `priority: -10` 盖住原生菜单；开合仍由宿主状态驱动（点可见按钮时仍点宿主隐藏的 `WorkspaceChip` 来切 `pickerOpen`，只是把锚点改到可见按钮上），选中仍走宿主的 `onPick`，所以草稿随工作区迁移、当前项高亮与宿主的选择语义都保留下来。菜单顶部是实时搜索框（按名字过滤、忽略大小写；标题为 `default-workspace` 的自动工作区显示当前语言的默认名），列表在 `min(38vh, 300px)` 内滚动，弹层本身按锚点下方剩余空间封顶（下方不足 230px 时向上翻），搜索行与「添加工作区…」行不随列表滚动。代价是这套菜单得跟着宿主的状态机走，宿主一改开合语义就要重新对齐。
- **菜单的每一行只写工作区名。** 每行只有文件夹图标 + 工作区名（不显示路径），菜单宽 300px，选中行带宿主同款 14px 勾选图标（`IconCheckOutlineRegular`，与原生菜单同一枚图形）和 `data-current` 高亮，↑ / ↓ / Home / End 移动、Enter 选择、Esc 关闭，活动行会滚进可视区；无匹配时给出「没有匹配的工作区 / 清除搜索」，一个工作区都没有时给出「还没有工作区」。添加工作区仍渲染宿主的目录流（`conversation.hero.workspace.directoryFlow`），沿用它的错误对话框并多一个「重新选择」；关掉皮肤时包装组件直接渲染原生 picker。代价是不显示路径，同名工作区只能靠所在分组分辨。
- **用量面板挂在欢迎页的开关上。** 标题下方那张卡只出现在欢迎页（`body[data-smooth-home]`，和隐藏输入卡片是同一个开关），新建会话的欢迎页仍只有标题与卡片，不画这块。形态照 `dsh-claude-style` 的 Studio 用量卡：12px 内边距、16px 圆角的卡，宽 `min(560px, 100%)` 居中在标题下，卡头左边是「概览 / 模型」两个标签、右边是「全部 / 30 天 / 7 天」三段区间。代价是首页的第一眼不再是空的输入框，多了一块要读的信息。
- **概览页先数字、再热力图、最后一句换算。** 六格数字依次是会话数、消息数、Token 总量、活跃天数、高峰时段、最常用模型（3 列 × 2 行，窄窗口降到 2 列），再是 26 周 × 7 天的热力图（周日起始，`grid-auto-columns:1fr` 让格子随卡宽保持正方形、间距 3px、圆角 3px），最后一句「你的 Token 用量相当于 N 本《…》」。热力图的四档亮度是当天占窗口内最高一天的比例（`20% / 40% / 65% / 100%` 混合 `--smooth-heat`，空白天是 `--smooth-text` 的 11%），所以忙季和淡季能分开；单元格悬停用 `::after` 显示「日期 — X Token」，最左、最右三列把浮层贴边对齐，避免被窗口裁掉；加载中整块画成 5% 高的骨架并轻微呼吸，解析失败（没有 Host 桥）则整块不画。代价是热力图是相对刻度，同一张图在不同人那里深浅不可比。
- **模型页是同一份数据的排行。** 列表按 token 排序：色块（按名次的蓝色阶梯）、模型名、token 数、占比，超过 6 行折叠成「再显示 N 个」。所有数字沿用宿主状态栏的 k/M/B 一位小数计数，计数类用千分位，所以面板和状态栏不会对同一个数给出两种写法。
- **数据来自 Host 半的 `usage` 动作。** 只读扫描 `$DSH_HOME/sessions/` 下每个会话日志（JSONL，逐批次 zstd 帧），按 `assistant/message` 结算折叠成「本地日 → {四类 token, 消息数, 24 小时直方图, 按模型 token}」，同一 (turn, step) 的再次结算只算最后一次（和宿主 token 投影的规则一致）；会话 id 取自日志所在的会话目录，所以「会话数」是区间内去重后的真实会话数，「高峰时段」取 24 小时直方图的峰值小时（`上午 5 点` / `下午 5 点`），「最常用模型」按 token 取第一名。日志按 (size, mtime) 缓存到 `$DSH_HOME/cache/smooth-usage-v2.json`，只重新解码写过的那些。代价是这块数字完全建立在日志格式上，格式一改就要跟着改解析，而它并不是宿主承诺的接口。

### 首页的分支与语音

- **分支来自宿主的工作区文件接口。** 首页通过 `remote.workspaceFiles.read()` 读取当前会话工作区的 `.git/HEAD`，支持子目录、worktree 和 detached HEAD；切换工作区立即清除旧分支，聚焦窗口及每 30 秒刷新。读取失败或没有 Git 仓库时不显示分支。
- **不显示待暂存文件数量。** 宿主没有公开完整的 Git status 接口，这个数字宁可不给，也不自己拼一个可能对不上的。代价是首页分支行只有名字，没有改动量。
- **语音输入沿用原生插槽。** 语音按钮只在宿主提供该功能时出现，皮肤不自建入口。

### 账号菜单

- **账号菜单在原生 `settings.launcher` 上加三块内容。** 头像资料、「剩余用量」和帮助入口，按参考图排列，字号跟随内容区；资料与登录状态来自原生 account store，不写死昵称或 Plus 套餐。设置、反馈、登录、退出确认和账号通知仍由原生组件处理，关闭皮肤后撤销覆盖。代价是这块内容只是原生菜单上的附加层，宿主改 launcher 结构就得重新对齐。
- **余额按十进制字符串处理，不合并币种。** 点「剩余用量」后余额面板在该项下方展开，右侧箭头旋转向下，再次点击收起；充值余额四舍五入显示两位小数，赠金钱包为空或为零时隐藏，有赠金时保留其小数精度，不同币种不合并。金额按十进制字符串处理、不改变接口原始数据；打开菜单和展开时都会刷新，支持手动重试，读取失败不冒充零余额。代价是每个币种各自显示，用户看不到一个「总共多少钱」。
- **弹窗从自己的左下角长出来。** `transform-origin:left bottom`，`.2s` 内 `scale(.82)→1` 轻微上浮淡入（`will-change` 让缩放走合成层）。资料卡插入弹窗后由皮肤显式武装入场动画（`data-smooth-account-open`），让可见的缩放等宿主行和资料卡都布局完再开始，不会因动画中途插入内容而卡住，`.12s` 的延迟版只作为未武装时的兜底；96% 不透明的面板也不再继承宿主 backdrop 模糊——那层模糊几乎看不出来，却会让每帧缩放都重算背景。代价是入场时机依赖「武装」这一显式信号，漏掉就退化到兜底的延迟版。
- **收回是复制一份菜单反向播。** 宿主会立刻卸载原菜单，皮肤在关闭事件里复制一份菜单（`data-smooth-account-leave`）原地播放反向动画：从 1 缩回 `.82` 并淡出（`.16s`），动画结束即移除副本；点击外部、Esc、失焦和点原生菜单项都走这条路，减少动态效果时进出都直接切换。代价是关闭期间页面上短暂存在两份菜单 DOM，任何假设「菜单只有一个」的选择器都得避开这个窗口期。
- **帮助是一个页内切换，不是新窗口。** 点「帮助」后下方操作区以 220ms 淡入滑动过渡切换为帮助链接，并可点「返回」恢复；四个入口分别为 Harness GitHub、开发者文档、社区插件和 cordis 论文，点击后通过宿主外链处理器在系统浏览器打开。切换期间保留原生设置、反馈和退出操作，非当前页不参与键盘导航——这样 Esc 和 Tab 的顺序不会因为多了一页而乱掉。

### 会话内容区

- **问答卡里的自由输入框不画焦点内描边。** 输入框获得焦点时不再画宿主那圈蓝色内描边，边框保持与空闲时同一档灰色，用光标本身提示焦点。理由是卡片里的输入框本来就只有一处可写，强描边反而把卡片框成第二个焦点环。代价是对不用光标提示的用户，焦点位置比原来弱。
- **行内代码跟文件引用同一个蓝。** 对话正文里的行内代码（反引号片段）用与宿主文件引用（file mention）相同的链接蓝 `--dsw-alias-link`，围栏代码块保持自己的语法配色、不跟着变色。理由是同属「正文里的代码标记」，两种蓝会给读者两个信号；围栏块已经有底色和语言高亮，不需要再借颜色。代价是行内代码在深色背景上的对比度跟着链接色走，标记色换成偏暗的选项时会弱一档。
- **强调色只有两枚。** `#8fb7ff`（品牌）与 `#ffcd96`（暖色点缀），前者用于可交互与聚焦，后者只做点缀。第三种强调色会把「哪个是重点」冲散，所以宁可让所有交互共用同一个蓝。代价是暖色能出现的场合很有限。
- **光感最先只落在局部。** 输入卡片、选中标签与导航项上曾有左上方向的轻微渐变配顶部内高光，输入框聚焦时不再叠加强调色反光（描边已去掉，靠投影与内高光分层）；按钮悬停和按下以 160ms 平滑明暗反馈，减少动态效果模式下直接切换。这样每个控件都能在不动布局的前提下给出「可点」的暗示。
- **后来整页退成扁平。** 页面按扁平处理后不再有「光感」层：卡片 / 面板顶部的白色高光与内阴影（原 `--smooth-light-wash` / `--smooth-light-edge`）、主面板投到侧栏的环境阴影（原 `--smooth-shadow-workspace`）、以及选中控件上的局部反光都已移除，表面改为纯色平铺，只保留菜单 / 弹层与浮动卡片必要的分隔阴影（`--smooth-shadow-1/2`）。代价是表面之间的层次只剩纯色差和这两级阴影来表达，立体感确实比带内高光时弱。
- **任务清单压紧标题栏与行距。** 原生任务清单采用紧凑标题栏与统一行距，进行中的任务有淡强调色背景；长任务标题自然换行，列表高度随窗口受限并保留内部滚动。展开与收起恢复原生即时切换，任务状态、计数和折叠继续由宿主处理——皮肤只改外观，代价是它不借机重排任务顺序，也不自己维护折叠状态。
- **问答卡片统一文字层次，逻辑全留宿主。** 原生问答卡片统一了题目、选项及说明的文字层次，说明独立分行，选中项使用淡蓝底色；长问题和选项可分别滚动，底部翻页与提交区保持可见，窄卡片自动重排。单选、多选、自定义答案、倒计时、草稿与提交逻辑全部保留原生实现，代价是卡片结构不能按视觉重画，只能用样式叠在原结构上。

### 滚动条

- **默认细线，滚动时才变粗。** 滚动时在 160ms 内变粗，停止 650ms 后用 280ms 渐细；保持原生拖动和固定轨道宽度，减少动态效果模式下直接切换粗细。理由是常驻粗条在长页面里一直占着视觉重量，而常驻细条在快速滚动时几乎指不出位置，动画让它只在需要时强调存在。代价是滚动过程中多了一点视觉扰动，截图或录屏时容易抓到粗细不同的两帧。
- **自定义滚动条只作用于应用表层。** 宿主没有全局滚动条规则，因此自定义样式只作用在应用自身的表层（会话滚动、侧栏、设置、菜单）；正文流内部的嵌套滚动容器保持平台叠加式滚动条，不为宽表格、代码块预留 8px 槽位。代价是正文里的宽表格滚动条形态和外壳不一致，换来的是不为几处横向滚动牺牲整列宽度。

### 启动动画与启动开销

- **首帧就是最终画面，全程没有主线程动画。** 启动层随宿主 index 一起注入，第一帧直接显示 FishLogo 的内联矢量鲸鱼：图标宽度 112–176px，深色显示白鲸、浅色显示黑鲸，没有文字、图标底板、边框、进度线或彩色光晕。结论是被「应用启动期间主线程很忙」逼出来的：唯一动作是挂在**外层 HTML 盒子**（不是里面的 svg）上的 CSS 摆动，`transform-origin:50% 60%` 配 `will-change:transform` 让它单独成层、交给 compositor——鲸鱼只光栅化一次，之后移动的是合成器里那张纹理，主线程被 bundle 解析和首次 mount 占满时它照跑。周期 2.4s，幅度 `rotate(-2.4deg)/translate(-.3px,-.5px)` → `rotate(1deg)/translate(.2px,.15px)`，比英雄区 hover 时更慢更小，掉一帧也看不出来。
- **英雄区那套 SMIL 摆尾没有被采用。** 它必须在主线程逐帧重算几何，正是启动窗口里最不该有的活。代价是鲸鱼不会真的摆尾，只有整只的轻微晃动。
- **进出场只有一次透明度，最短停留 1500ms。** 鲸鱼自身没有入场或出场动画——开场层首帧就是最终样子，只在交接时 340ms 淡出一次，随后外壳各部件用同一组纯透明度淡入（错落靠延迟，没有位移）。开场等应用挂载后才淡出，保留启动动画开关，系统开启「减少动态效果」时自动跳过。代价是开场没有任何进度类信号，启动特别慢时只能看着鲸鱼。
- **设置页的「预览」重播同一份定义。** `设置 → Smooth → 启动动画` 右侧的按钮会用同一份标记、同一份样式、同一组时长就地重播一次，与真启动完全一致，点完即时可见，不用重开应用。

### 窗口与桌面尺寸

- **启动窗口默认 1440 × 900，可关。** 在 `设置 → Smooth → 启动窗口尺寸` 里可直接改宽高（带开关，可关掉交还给应用自己的 1280 × 820），改宽高立即生效，下次启动同样沿用；开关只决定下次启动用不用这个尺寸，不碰当前窗口。
- **窗口是隐藏创建的，所以用户看到的第一帧就是最终尺寸。** 桌面应用的主窗口由 `lib/main.js` 的 `createWindow()` 创建：1280 × 820，最小 520 × 600，只有在 `loadURL` 完成后才 `show()`；插件注入 index 的内联脚本运行在文档解析期，正好落在这个窗口不可见的区间里。这是尺寸能无跳变生效的唯一窗口期，代价是加载完成前给不出任何可见反馈。
- **尺寸只在两个时机请求，`resizeTo` 是唯一的通道。** 启动脚本在窗口仍不可见时设一次，客户端半只在用户改宽或高这两个数字时再设一次（点开关不算：它只决定下次启动用不用这个尺寸，永远不碰当前可见窗口）；模块激活本身不请求尺寸，切换主题预设、启动动画等其它设置也不请求。原因是 `outerWidth` 含窗口边框、通常不等于配置的宽度，旧实现会在每次切换时调用 `resizeTo` 并把窗口蹭偏；现在比较尺寸时留 ±2px 容差，边框造成的那 1px 差值不再被当成「尺寸不符」。代价是 2px 以内的请求会被静默忽略，想要严格对齐只能靠别的手段。
- **每个渲染会话只套用一次。** 启动脚本用 `sessionStorage` 的 `dsh-smooth-skin:session-window-sized` 标记保证这点：F5 / Ctrl+R 保留用户拖过的尺寸与位置，新应用窗口或下次启动才重新套用并居中。存储里缺少该字段时，启动脚本沿用与 `normalizeSize` 相同的默认值，两半不会给出不同答案；旧状态最明显——启动脚本按默认值设好，激活再设一次就会看到窗口突变。
- **居中只发生在启动，改尺寸只改大小。** 脚本会把窗口在屏幕可用区域里居中（`availLeft` / `availTop` 一并计入，多显示器不会算到主屏原点上），`moveTo` 与 `resizeTo` 走同一条渲染进程→主进程的窗口通道；拿不到可用区域时跳过居中，避免把窗口挪到一个编造的原点。在设置里改尺寸时，每次应用前记下窗口原点，`resizeTo` 之后 `moveTo` 回同一个原点（并按可用区域收窄，窗口变大也不会有一部分跑到屏幕外），所以改动宽高、包括连点数字步进都只改大小，不会把窗口一点点蹭走；点开关则连一个窗口请求都不会发出去。代价是位置正确性依赖「渲染进程能拿到可用区域」这一前提。
- **超出可用区域就收窄，低于最小值就抬到 520 × 600。** 请求超过屏幕可用区域时按可用区域收窄——比屏幕还大的窗口会把标题栏推到够不着的地方，而渲染进程本身没有移动窗口的能力，用户没法靠拖标题栏自救；低于应用最小值时抬到 520 × 600。

## 三、输入卡片

输入卡片是这份皮肤改动最密的地方：上下两层结构、上方小字入口、贴边展开的模型面板和自绘光标都挤在同一块面上。下面按结构、交互、数据与回退分组，每条先给结论，再给理由和代价。

### 卡片结构与高度

- **输入区拆成上下两层。** 上层是一块**独立描边的输入区**（1px `--smooth-line-strong`、16px 圆角、输入底色，发送键单独放在它的右上角），下层是页面底色上的功能行。
  - 描边独立，是因为卡片边界要由皮肤决定，而不是沿用宿主那层容器的视觉。
- **欢迎页与对话中结构一致：同一块描边输入区。** 没有图片时最小高度 42px（上下内边距各 10px，字号仍是 14px）。
- **两个场景被收成同一块面。** 占位提示两处都是单行省略（宿主在欢迎页原本会折成两行）；对话中卡片下方那条渐隐也改为收到本皮肤的地板色，而不是宿主基色。代价是地板色改一次，两处要一起改。
- **卡片高度交给宿主自己的排版。** 工作区、分支与自动审查都收在卡片底部的功能行里，不再在顶部占一行。欢迎页的栈宽与卡片上限都取 `--dsh-composer-card-max-width`，皮肤不再给它 150px 的最小高度——那段空白会让输入框看起来没被设计过。
- **功能行左侧只有「自动审查」与加号，右侧整行留给模型与强度选择（靠右对齐）。** 加号在前、权限档在后。
- **文本区随内容增高，最高 300px（小窗口不超过 40vh），同时受页面剩余高度限制，超出后内部滚动。** 两道上限叠在一起，是为了在任何窗口高度下都不把下方 dock 顶出视野。
- **占位提示缩短为「描述任务，/ 调用指令，@ 引用文件或对话」。** 工作区选择、不可用、计划和运行状态提示仍沿用原生内容——那些要的是准确，不是简洁。
- **发送键沿用皮肤原来的 32px 主题蓝圆球。** 钉在输入区右下角（没有图片时输入区只有一行，看起来就是右上角）；空内容时灰显，悬停提亮。

### 图片与附件

- **有图片时，正方形缩略图横向排进同一个描边框。** 124 × 124、16px 圆角、`object-fit:cover` 裁切、自身不描边；缩略图与输入区共用一条外框，图片和文字之间没有分隔线。共用外框是为了让图片读成输入区的一部分，而不是贴进去的另一个控件。
- **原生附件条本身只有 64px 高，会把方形预览裁掉一截，所以轨道项一起抬到 124px。** 代价是附件行高度翻倍，图片一出现卡片就要长高。
- **图片出现时输入区向上平滑展开（`.15s` 缓出，减少动态效果时不播动画）。** 向上展开是为了让发送键和输入起点待在原地。
- **占位提示与发送键落到图片下面一行。** 图片占的是同一块描边框的上半部分，文字行必须让位，否则占位会和缩略图叠在一起。
- **加号留在功能行。** 附件入口不挤进图片轨道，轨道里只放已被选中的预览。

### 工作区、分支与模式入口

- **工作区、分支与代理模式选择以小字排在输入框上方左侧。** 统一 12px、20px 高、同一条基线；欢迎页卡片有这些，对话里没有工作区/分支。
  - 同一条基线是硬要求：三个按钮高度本来就不同，不共用基线整行就会显得没对齐。
- **整行与上方标题之间留 34px（卡片加 margin-top），不再贴着标题。** 这 34px 是给「这是一张卡片」留的气口。
- **工作区按钮点一下宿主隐藏的 WorkspaceChip，只借它切换宿主的开合状态**（菜单本身由皮肤画），锚点改到可见按钮上。代价是皮肤依赖宿主的内部组件，宿主改结构就会断。
- **分支按钮打开 Git 菜单：支持搜索、切换分支、创建并检出新分支，当前分支下显示未提交文件数。**
- **这两个入口由 Host 半的私有 `/smooth-skin/git` 监听提供**（固定 `git` argv、只接受带令牌的本地请求）；令牌与回退规则见「私有桥与回退」。
- **模式入口保持 13px、32px 高。** 代理模式选择（标准模式 / 创造模式）紧接在分支之后，不单独占一行。

### 模型入口与思考强度面板

- **模型入口保留原生紧凑控件**（模型名 + 1017 徽标 + 当前 High + 右侧箭头）。保留原生外观，是因为它承接的是用户已有的肌肉记忆。
- **点击时在它上方展开一张面板。** 面板内容是模型名（点它滑到模型列表页）和一条不带刻度文字的思考强度滑杆；当前挡位（Off/Low/High/Max）显示在模型名上方，切换时轻微上浮淡入一次。
  - 滑杆不带刻度文字：挡位名已经写在上面，重复一遍只会让面板变吵。
- **原生模型菜单被这张面板替换。** 面板有两页——思考强度页和模型列表页；点模型名时两页像账号菜单滑出帮助页那样横向淡入淡出（`opacity .2s` + `translateX 14px`、`.26s` 高度过渡，面板高度跟着当前页走），选中模型、按返回或 Esc 再滑回强度页。
- **面板的展开/收回只做轻量动效。** 首帧就是最终尺寸（不等待测量、不做高度展开），只叠一个 `.16s` 的淡入 + 6px 上浮（`transform-origin` 贴底），点下去立即可见内容；关闭（点外部、Esc、或再点一次模型入口）用 `.15s` 淡出下移，`.16s` 后卸载 portal；减少动态效果时两个方向都直接切换。代价是打开时做不了高度展开，因为那需要先测量。
- **面板挂在 composer 的浮层槽 `conversation.input.overlay`。** 它随任何会话的输入卡片渲染，所以新建会话的欢迎页点模型按钮也是同一张强度面板，而不是宿主原生模型菜单；原来的 `conversation.input.right` 要等输入状态就绪才渲染，欢迎页不满足，原生菜单因此漏了出来。
- **前提是客户端的 inject 里声明了 `remote.session`。** `modelDirectories.directoryFor(sessionId)` 要解析该会话的 remote 绑定，Cordis 会按调用方插件的 inject 校验 `remote.session`。
  - 缺了它，全新会话（输入框还空着）解析模型目录会抛 `cannot get property "remote.session" without inject`；面板宿主判定未就绪、触发器监听装不上，点模型按钮就落回原生菜单，要等第一次输入把会话绑定起来才恢复。
  - 现在 inject 已声明，全新会话空输入直接点也能打开强度面板。
- **`auto` 按钮把等级交还 Provider 默认。** 当该模型的目录提供宿主自己的 Default 思考（宿主菜单那条「Default」只在 `defaultEffort` 未固定时出现）时，挡位名左侧多一枚 `auto` 小按钮。
  - 点击按宿主原生菜单同样的方式提交（请求里不带 `reasoningEffort`），把推理等级交还给 Provider 默认。
  - 此时挡位名显示 Default、滑杆暂时变暗表示它不再决定当前等级；再拖动或点滑杆任一挡位就回到显式挡位。
  - 代价是「当前等级」有两种来源，UI 必须能把两者区分开。

### 滑杆、填充与粒子

- **轨道、填充、滑块和每个挡位的浅色小点各用独立的双色 token。** `--smooth-model-track/blue/thumb/dot`：浅色是浅轨深蓝，深色是深轨亮蓝。分开是为了同一个部件在两种主题下能各自偏色，而不是共用一个 accent。
- **滑块放大到 28px，本身是一颗跟随挡位滑动的球。** 原生滑块只保留命中区域并隐藏绘制；按下有平滑缩放和阴影过渡。
- **`--smooth-model-ratio`（0–1）同时决定蓝色填充宽度和球的 `left`。** 该值用 `@property` 注册成可动画的 `<number>`；点轨道或按方向键时只对**这一个数**做 300ms 缓动，填充边缘和球因此在每一帧都重合。
  - 填充按轨道内宽算，减掉左右各 1px 边框，正好停在球心；这样不会出现球到了、蓝条还在半路的情况。
  - 代价是所有视觉都挂在这一个自定义属性上，改轨道结构时这条换算要一起改。
- **蓝色填充到选中挡位**；拖动经过挡位或点轨道时即时通过宿主模型目录写入 `reasoningEffort`。
- **每个挡位在轨道上有一个浅色小点，画在蓝色填充之上、滑块之下。** 已填过的挡位仍能看到小点，滑块只盖住它正停住的那个挡位点；层级反了，已选挡位的点就会消失。
- **按住拖动时滑块跟手。** 指针位置换算成 0–1 的比例直接写到滑块元素的 `--smooth-model-ratio` 上，不触发 React 重渲染，所以面板里的图和粒子不会在拖动中重建；滑杆容器同时关掉过渡，填充和球一起直接跟手。
- **松手后把属性交回当前挡位的比例，滑块带 `.3s` 缓动落到最近的挡位。** 松手只补一次最终确认，不再等防抖计时。
- **每次展开面板时滑块直接停在当前挡位。** 属性在首帧绘制前就写好，那一帧临时关掉过渡（借用 `is-dragging`），下一帧再摘掉，所以不会看到从最左边滑过来的回放。
- **拉到最高挡位时，滑块上出现一串向左跑的粒子。** 96 个，起点、行程、速度、大小、透明度各自不同。
  - 起点按 0.38 次幂压向右侧，左三分之一基本空、右半段最密；大小与亮度也随位置加权，所以是从滑块附近涌出、向左飞散、由多到少。
- **进度条上同时叠一层随机移动的光层。** 4 小片很淡的白光斑（直径 32–68px，只比轨道高一截），蓝色底色保持原样、不被染白。
  - 绝大多数位置仍是纯蓝：光斑透明度只有 0.13–0.25、`screen` 混合，只在经过的地方把蓝条提亮一点点（单点峰值约 +30/255 的红绿分量）。
  - 光层裁在蓝色填充的宽度里（同样吃 `--smooth-model-ratio`），白只会落在蓝条上，不会溢到滑块右边的空轨。
- **每片白光用 `translate:-50% -50%` 把圆心压在轨道中线上。** 否则圆心会掉到 24px 条子下方，只剩近乎透明的边缘，等于看不见。
- **z-index 与运动参数。** 光层 `z-index:1`（填充之上、粒子之下）；各自有起点、水平/斜向漂移方向与 4.5–8.5s 的往返周期（水平最大约 80px、纵向最多 14px），互不同步，看起来就是几小片白光在蓝底上随机游走。
- **离开最高挡位就撤掉粒子与光层，减少动态效果时不画。** 这两层只在「已经到顶」这个状态里成立，常驻会变成噪音。

### 上下文占用环

- **卡片顶部没有单独的信息条。** 轮次/步数、tok/s、token 总量与缓存命中、上下文环这几组状态仍由宿主的 dock 渲染在卡片下方居中，不再被钉到功能行上。
- **但输入框下方那条宿主数据区（就是上面这几组状态和它自己的上下文环）整行移除**，改为在模型选择按钮左侧画一枚 22px 的占用率圆环：蓝色弧线、浅灰底环、百分比居中，环的粗细与配色取 `--smooth-accent` 与主题 token（样式参考 `assets/occupancy-ring/` 的环形图）。这些数字多数时候只值一个数字，摊成一行反而没人看。
- **点击圆环弹出浮层。** 顶部是「上下文已用 N%」与 `~已用 / 窗口`，下面一条系统提示词 / 工具定义 / 对话消息的三段占比条和带 token 数的图例。
- **浮层下半是两块明细。** 「会话统计」（模型用时、工具调用用时、首 token 平均、输出速度）与「Token 用量」（缓存命中、未缓存输入、缓存读取、输出）。
- **数字全部直接取宿主的 `contextPressure` / `contextBreakdown` / `sessionStats` / `tokenUsage` 四个投影。** 口径与原来的上下文环和两个统计弹层一致；面板沿用宿主的浮层样式，并在 Esc 或点外部时关闭。不自算是因为口径一分叉，两处数字就会互相打架。

### 光标与草稿清空

- **输入光标由皮肤自己画：一个 2px 的竖条。** 位置跟着选区矩形走、以 .1s 缓动滑到新位置，闪烁从硬切改成柔和明暗。
- **输入法组合期间也沿用这支竖条（落在拼音末尾）。** 减少动态效果时竖条不闪；组合期不换回原生光标，是为了不在打字中途改变视觉基准。
- **软换行（Shift+Enter）之后按 DOM 位置重建插入点。** Lexical 会把选区锚在段落元素上，直接量选区矩形只会得到整段的外框或空矩形，竖条因此跳回句首；现在换行后的内容另起一行，段尾 `<br>` 之后落到下一行。代价是插入点要自己按 DOM 算一遍。
- **几何完全量不出时交还原生光标，不再猜一个起点。** 猜错比不显示更糟。
- **发送后由 `MutationObserver` 把竖条归位到文本起点。** 宿主以程序化方式清空草稿时，浏览器会把 DOM 选区重新锚到空编辑器上却不派发 `selectionchange`，光标此前因此停在发送前的位置；现在皮肤同时跟随编辑器自身的内容变化，内容变为空时直接把竖条归位到文本起点。
  - 归位跳过缓动、不做从旧位置滑回来的动画；清空后的光标状态与刚打开输入框时一致。
  - 代价是多一个常驻观察者。

### 插图与 Provider 边界

- **思考强度插图只属于 DeepSeek：只有模型目录里 DeepSeek、DeepSeek Account 这两组的模型才显示这块背景。** 其它 provider（例如 xiaomi）保持没有插图的纯面板；挡位文字和滑杆对所有带 reasoning 的模型照常显示。插图是这两组模型的品牌资产，套到别家模型上会被读成皮肤自己的风格。
- **整块背景（插图连同底部虚化）比媒体区顶边低 6px。** 图片和渐变一起下移，不会出现「只有图动了、虚化没动」。代价是插图不能按媒体区顶边对齐，而要按这条偏移算。
- **四张挡位图常驻 DOM 交叉淡入。** 面板打开时按当前挡位显示对应插图（先匹配思考挡位 id，匹配不到按位置换算），拖动或点标签换挡时交叉淡入；常驻是为了换挡时不等待解码。

### 私有桥与回退

这一节是这条私有回环（`/smooth-skin/git`）的令牌、重启与回退规则；端点与 `git` argv 的约束见「工作区、分支与模式入口」。

- **令牌写在 `$DSH_HOME/cache/smooth-bridge-token`，并跨激活保留。** 页面手里的那份不会因为重新激活、重建或重启而失效，否则旧页面会被 403 挡在门外直到刷新。代价是凭据落盘，清理要自己记得。
- **Host 半更新后需完全退出 DSH 再启动。**
- **Host 未加载时分支按钮回退为复制分支名。** 回退而不是报错，是因为用户此刻要的只是一个分支名。
